Collective Knowledge
web-workflow demo

Students push text; the instructor reviews, edits and approves — from the command line or entirely in the browser. This page hosts the two web artifacts of that workflow, built by the real tool from a real demo repository.

📖 The published book

What readers see after each merge. Tap any paragraph to see who wrote it (git blame, paragraph by paragraph) and who vouches for it. Vouched paragraphs carry a green edge.

 🔍 Rendered diff of a pending change

Alice proposes replacing α with κ in the heat-equation chapter. This is the page CI attaches to every pull request — insertions green, deletions red, and the changed symbol inside the typeset formula individually highlighted.

How a change flows through the system

  1. Student: book change new → edit → book save → book submit
  2. A pull request appears on the course Forgejo; CI posts a rendered-diff link (the page above) as a comment.
  3. Instructor reviews from the PR page: discuss, request changes, or press the merge button — or does the same from the CLI with book review / book approve --vouch.
  4. On merge, CI rebuilds and redeploys the book (the site above), with the student's authorship preserved for paragraph-level blame.

The review surface itself — PR pages, comments, the merge button — is Forgejo, a server, so it can't be hosted on GitHub Pages. This demo shows the two custom static artifacts the system adds around it. Deployment of the full stack: infra/README.md in the repository.
